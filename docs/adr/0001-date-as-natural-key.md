# Дата записи — естественный ключ, время не хранится

Запись хранит только календарную дату, без времени суток, и дата является уникальным ключом: на один день приходится не более одной Записи. Повторное сохранение на занятую дату заменяет существующую Запись (с подтверждением в UI).

## Рассмотренные варианты

Альтернатива — хранить момент времени (дата + время) и допускать несколько Записей в сутки: так устроено большинство трекеров веса, и взвешивание действительно происходит в момент, а не «в день». Вариант отклонён: без отображаемого времени две Записи за один день визуально неразличимы в Истории и выглядят как дефект, а сам сценарий (утреннее и вечернее взвешивание) для этого приложения не нужен.

## Последствия

- Схема БД и весь UI исходят из уникальности даты; возврат ко времени потребует миграции данных и переделки Истории и формы ввода.
- Редактирование Даты записи может привести к коллизии с существующей Записью — UI обязан спросить подтверждение на замену.
- Будущие даты не запрещены, поэтому «последняя Запись» и «последняя Запись не позже сегодня» — разные вещи: форма предзаполняется вторым.
